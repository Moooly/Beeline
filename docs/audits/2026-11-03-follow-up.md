# Follow-up audit implementation — 2026-11-03

This follows the read-only second audit and the first implementation pass. The changes remain in the working tree; no commit or push was requested for this pass.

## Correctness and reliability

- **Literal identifiers:** BEELINE's shared CSV reader preserves numeric-looking row names and values such as `NA`. Raw headers are checked before pandas can rename duplicates. Host edge-table parsers preserve source/target names as strings. PIDC restores literal labels after its upstream numeric inference. GRNScope's expression reader also preserves identifiers, validates duplicate headers, and preserves the original index-header convention. The preprocessing transformation signature advances to version 2 so older cached transformations are not silently reused.
- **GRNVBEM:** reject absent headers, truncated rows, and invalid/nonfinite scores. Validate the original six-column output inside the container before compaction, so compaction cannot turn a failed/truncated result into a successful empty network. Valid header-only empty networks remain supported. The validator works with the old awk version shipped in the existing image; it does not depend on POSIX character classes unsupported there.
- **GRISLI:** validate raw rank fields before numeric conversion. Blank/text/nonfinite/out-of-range ranks fail clearly instead of becoming strong edges. Python matrix parsing enforces the same finite/range rules in full and capped paths.
- **CellOracle:** the host parser uses the shared deterministic reducer, filtering self-links, repeated edges, and nonfinite scores before top-K selection. The header and row shape are checked.
- **SCRIBE:** estimate dense-result, pair-graph, expression-copy, parent-merge, and runtime memory from data dimensions. Reduce pair-worker count when necessary; reject jobs that cannot fit even one worker within the estimate. The estimate is intentionally conservative and is not a measurement of every possible R/Monocle allocation. Recomputed-pseudotime diagnostics now have separate filenames per trajectory. The website option is labeled **Use supplied pseudotime**, retaining the existing `ignorePT` key and boolean mapping.
- **SCRIBE multi-delay bug found during validation:** the bundled native `extract_max_rdi_value_delay` initializes `max_delay` outside the pair loops and fails to reset it for each pair. If the first tested delay is optimal, a previous pair's delay can carry over. The wrapper now computes the first maximizing delay independently per pair. A single supplied delay is unchanged. Conditioned networks using multiple delays can change; rerun affected existing results.
- **SINGE:** shell failures now propagate immediately instead of being masked by subsequent shell conditions. Invalid replicate counts are rejected.

## Performance and memory

### PIDC

Cache the Gamma distribution and fallback statistics once per gene, rather than refitting the same distribution for each edge. Keep the original pairwise fallback behavior. Capped output selects directly from the weight matrix and avoids constructing and globally sorting a full array of Edge objects. The cubic PUC computation is unchanged.

Warm inference comparisons inside the existing image, one CPU, median of three trials:

| Fixture | Previous inference | Updated inference | Approximate speedup |
|---|---:|---:|---:|
| 19-gene GSD sample, 180 cells | 0.0073 s | 0.0024 s | 3.0× |
| 80-gene synthetic, 180 cells | 0.397 s | 0.0877 s | 4.5× |
| 180-gene synthetic, 180 cells | 2.659 s | 0.946 s | 2.8× |

All full-network edge identities/weights matched exactly; capped output matched an independent full-sort oracle for K=1, K=5, and K above the gene count. Degenerate-distribution fallback cases matched exactly. Final checks also exercised zero-prefixed numeric gene labels.

These are inference-stage timings, excluding container startup, file loading, and discretization. They are local amd64-emulation fixtures, not a claim of equivalent speedups for complete production jobs.

### GENIE3 and GRNBoost2

Run top-K reduction in the same Dask task as each target's fit, before concatenating target results. This limits intermediate network tables and transfer sizes without changing fitting, seed, or hyperparameters. Full versus bounded output matched exactly for both algorithms on the 100-gene/180-cell, 30-tree-or-round fixture. No production runtime percentage is claimed.

### SCRIBE

Workers return only their assigned pair values rather than full dense matrices. The parent reconstructs the final matrices once. The native calculation still allocates dense arrays inside each worker, so the data-dependent memory guard remains necessary. Checks cover RDI/uRDI and conditioned variants with 1, 2, and 4 workers and delay sets `[1]`, `[1,2,3]`, and `[3,1,5]`, against an independent per-pair maximizing-delay oracle.

### SINGE

Replicate tasks reuse one short-lived container per allocated worker slot, preserving replicate concurrency and per-replicate timing files. Tasks inside each slot run sequentially and share the MATLAB extraction cache. There is no persistent container service left running after a job. Preparation and aggregation remain separate stages.

A 12-gene/80-cell, three-replicate, one-worker comparison retained exactly the same nonempty 36-edge network. Full runner time decreased from 17.45 s to 15.05 s (about 14%) in one local comparison. More repetitions and production-scale profiling would be needed for a general speed claim. Unit checks verify complete replicate coverage with multiple slots and failure propagation.

### Host matrix cache

Keep at most four source frames within a 256 MiB LRU budget; oversized frames are not retained in the shared cache. Release each runner's selected expression/pseudotime copies after completion or failure, so standalone batch runner lists do not retain all prior matrices. Keep per-run mutation isolation.
